# 程式碼規範

狀態：訪談第四輪已確認的規範。目標是清楚可讀、責任明確，且能在首版完成後逐步擴充。

## 資料、規則與呈現

- 種植物數值、圖片與配方使用 ScriptableObject 設定資產。
- 設定與執行時狀態分開，不直接把 ScriptableObject 資產當作存檔狀態。
- 農田狀態、成長、收成及資源運算放在與畫面分離的 C# 邏輯。
- 場景與 Prefab 上的元件負責呈現、輸入及資料綁定，不承擔全部遊戲規則。
- 模型透過 C# 事件通知變更，顯示端負責適當訂閱與解除訂閱。

## 抽象與行為

- 普通植物共用成長邏輯，時間、產量、外觀等差異使用資料設定。
- 不同行為使用獨立類別實作，依需求採抽象基底或介面；避免以單一大型函式大量判斷種類後執行不同規則。
- 不為每個類別強制建立介面，不為每個物品種類建立子類別。
- 設計模式須解決具體需求，首版不引入大型框架或 DI 套件。

## 維護習慣

- Inspector 欄位優先使用 private 搭配 SerializeField，不為了 Inspector 任意公開欄位。
- 參照優先明確指定，避免隱藏依賴與到處搜尋場景物件。
- 註解解釋規則、限制與取捨，不逐行翻譯程式碼。
- 重複 UI 項目使用預製資產，遵守 project-standards.md 的場景與 Prefab 原則。

## 時間與存檔

- 生長按實際經過時間累積進度；增益僅影響生效期間，不回溯修改既有進度。
- 在線及離線推進遵守同一套遊戲規則，負時間差視為零，首版不做防作弊系統。
- 本機單一存檔，包含版本欄位；重要操作後儲存，另有定時存檔。
- 農田批次收成設定須隨存檔保存，且跨收成與重種保留。

## 驗證

- 核心規則使用 EditMode 測試，優先覆蓋資源扣除、收成、時間推進及存讀檔等有實際風險的情境。
- 不建立只重述實作、沒有實際驗證價值的測試。
- 場景、Prefab、UI 與操作流程在 Unity Play Mode 驗收。
